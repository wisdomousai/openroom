# 1:1 tutoring UX audit — 6 November 2026

## Scope

Thirteen scenario audits covered the 1:1 tutoring loop on six surfaces: workspace, deck editor, live console, participant phone, learner page (`#/learn`), Desktop. They also covered the agent prep path (MCP, CLI, session API) and the public site and manual. Each auditor drove its own disposable local runtime (`bun run verify:browser --serve`: empty storage, demo sign-in, the real Worker, database and live-session objects) through separate tutor and learner browsers, at 1280, 768, 390 and 320 pixels wide where they apply. A skeptic per scenario then tried to refute each finding, re-driving its own runtime when the evidence was ambiguous, and checked every proposed fix against AGENTS.md and DESIGN.md. A coverage critic added three follow-up audits: a second lesson through the UI, real microphone and listening media, and the phone soft keyboard on short screens.

Screenshot paths below are relative to the run's scratch directory (`audit/<scenario>/`, `verify/<scenario>/`); they are not committed.

### Participant phone app

Fix the phone join and live screens in apps/participant and the packages they render. Layout and input: the page scrolls below 640 px and in landscape (learner-live-01 and gap-phone-01, -03, -05 share one cause), controls reach 44 px, overlays use the one overlay shadow, accent keys insert at the caret without leaving the field, typed gaps become inline inputs with lang and autocorrect hints, drafts survive a pause, and lookup strips punctuation, maps error codes, handles Escape and focus, and the worker retries a capitalised word in lower case. States: the SDK treats 401, 403, 404 and 410 as a closed lesson and stops polling, online and visibility events clear the offline banner, an early link arrival waits and retries, join failures map by error code with one message for an ended session or a wrong code, the ended view drops Leave and the handle notice, the Reading choice survives a question, listening controls render below the slide plate with a participant-facing audio error, and reveal and ranking use interactionStatus and a shuffled start. This cluster owns the SDK, so it also adds an optional identityMode to StageSnapshot for live-console.

## Open decisions

### D1: How does a tutor who works only in the browser start a named (identified) lesson?

Findings: start-join-01, editor-authoring-04, site-manual-01. Cluster: agent-surface.

- **Identified stays an agent-door feature**: The prepared outline sets identityMode and deck_start or the CLI return the finished join URL that already carries the student link (agent-path-04). The manual says the browser has no named-join control. No credential-boundary impact; a browser-only tutor runs pseudonymous lessons.
- **Console action Copy student link**: In identified sessions the Session menu offers Copy student link: the tutor pastes the student orlnk_ link once and the console builds /join/?code=..&link=.. locally without storing it. Gives browser-only tutors a path with no server change, but the presenter then handles a credential, which needs a credential-boundary review.
- **Deck-level identified switch**: A continuity-gated switch writes defaults.identityMode through outline-edit.ts, classified in outline-fuzz.ts, exposed as an EditorServices slot (absent slot means no switch). Adds a new deck-level setting, still needs a link-composing step, and free accounts get 403 at start.
- **Link-only join resolved by the Worker**: /join/?link=orlnk_.. resolves the live session through sessions.context_id and returns only a participant token. Creates a second association path, which AGENTS.md forbids, and is ambiguous when a context has several live sessions; needs a credential-boundary review.

Recommendation: Keep identified an agent-door feature. It leaves the credential boundary and free live sessions untouched, matches how the manual already describes identified mode, and agent-path-04 closes the practical gap by returning the finished URL. Revisit the console action only if tutors without an agent ask for it.

### D2: What should Start session do when the same deck is already live for the same student?

Findings: start-join-02, second-lesson-09, live-console-01, agent-path-05. Cluster: workspace-library.

- **Replace Start with Rejoin while the deck is live**: Stops a second concurrent session of one deck in the inspector, editor top bar and Presenter. Acts as a lock and bends the file model, where a deck can be started more than once.
- **Keep Start, add a quiet Live now - Rejoin cue and one confirmation**: The inspector, editor top bar and Presenter show Live now - Rejoin beside Start session; pressing Start while a recoverable live session of this deck and student exists asks once: rejoin it, or start another. Needs deckId and context on MySession. Escape stays the documented exit after armed lookup is cancelled first.
- **Leave Start as is and only disambiguate Live now rows**: Rows name the student (second-lesson-01, which ships regardless). Silent double starts remain possible.

Recommendation: Keep Start, add the quiet Rejoin cue and a single confirmation. It follows the file model in AGENTS.md (Start always files a new session, Live now is a state of now) while ending the silent duplicate. The agent API stays free: an additive requestId in agent-surface covers retries.

### D3: Does the teacher UI keep its classroom phrasing in one-to-one lessons?

Findings: start-join-13, live-console-13, editor-authoring-13, onboarding-07. Cluster: live-console.

Change Prepare workshop recap to Prepare recap, the welcome card audience question, the name placeholder to e.g. Camille, and the plural Students language label. No documentation conflict; some class wording stays visible to tutors.
- **Neutral wording everywhere**: 2 questions on rows, Prepare recap, Everyone is disconnected. Requires amending AGENTS.md, DESIGN.md and TERMINOLOGY.md first, then code, tests (contents-meta) and the manual. One copy set for every experience.
- **Experience-aware noun through an optional EditorServices slot**: Tutoring rows read 2 ask the student; an absent slot means the class. Acceptable under the no-global-isTutoring rule only if the slot changes copy and never tools; adds slot plumbing and two copy sets.

Recommendation: Keep canonical strings and change only the outliers. The canonical phrases are mandated in AGENTS.md, DESIGN.md and TERMINOLOGY.md, groups are a first-class tutoring concept, and the editor may not import from apps/.

### D4: What does the participant screen show for a one-learner session?

Findings: learner-live-13, gap-phone-soft-keyboard-and-short-viewport-12, learner-live-08, live-console-07. Cluster: participant.
